# tools/ —— 走查与交付整理工具（开发用，非交付物）

这个目录**不参与原型运行**：原型本身是零依赖的纯静态站点，`docker compose up --build` 也不会用到这里的任何东西。
两个脚本，对应交付物可复核性：

| 脚本 | 作用 |
|---|---|
| [`walkthrough.js`](walkthrough.js) | 真实点击式自动走查，复现《[`docs/04-走查记录.md`](../docs/04-走查记录.md)》里的断言 |
| [`fix_prototype_pdf.py`](fix_prototype_pdf.py) | 整理原型图 PDF：去掉重复页 + 补编号书签 |

## 怎么跑

```bash
# 1. 先把原型跑起来（仓库根目录）
docker compose up --build          # 或 python -m http.server 8080

# 2. 另开一个终端，装依赖并执行走查
cd tools
npm install
node walkthrough.js
```

默认目标地址是 `http://localhost:8080`。需要换端口或指定浏览器时：

```bash
BASE_URL=http://localhost:8081 node walkthrough.js
CHROME_PATH="/path/to/chrome" node walkthrough.js
```

脚本会真实点击页面上的按钮（不是只读浏览），逐条打印断言结果，并在结尾给出
「通过 N 项 / 失败 M 项」的汇总；有失败时退出码为 `1`。

## 走查覆盖

| 路径 | 内容 |
|---|---|
| 路径 1 | 主流程：建立协作 → 完成事务 → 家属端只进日志、不打扰 |
| 路径 2a | 语音识别有误 → 老人纠正 → 结果正确 |
| 路径 2b | 取消 / 撤回求助 → 老人端与家属端状态一致 |
| 路径 2c | 家属改期 → 必须老人点头才生效 |
| 路径 3 | 失败与无法继续：连续听不清 / 家属未回应 / 网络失败 |
| 路径 4 | 角色间协作：老人求助 → 家属回应 → 老人收到回执 |
| 其他 | 恢复初始状态、全部页面与状态路由可达性、全程无 JS 报错 |

## fix_prototype_pdf.py —— 整理原型图 PDF

`prototype-images/安安-原型图.pdf` 由 32 张画面排版而成，原始文件有两个毛病：
有 9 张截图被整页重复渲染（导致 PDF 变 37 页、与编号对不上），而且没有书签。
这个脚本做「去重 + 补书签」，每步都校验，任一步不过就不写回原文件。

```bash
pip install pypdf
python fix_prototype_pdf.py ../prototype-images/安安-原型图.pdf
```

- **去重**：只删「自身没有编号标签、且图片指纹全部出现在下一页」的页 —— 只删纯重复，不动任何独立画面。
- **校验**：删完后重新比对全部图片指纹，集合必须与删前完全一致；否则放弃，原文件不动。
- **书签**：从页面上的编号标签文本（`21_F1_家属端_首页_正常日`）自动建立编号 → 页码映射，
  写入两层大纲（老人端 E1–E17 / 家属端 F1–F9）。不改变画面内容与分辨率。
- 原地更新前会把原文件备份到系统临时目录，不会把备份一起提交进仓库。

整理结果：**37 页 → 28 页**，31 张编号全部覆盖，书签 33 条。

## 两个实现上的注意点

1. **每个流程开头都要整页重载**：原型状态只在内存里，但仅修改 URL 的 hash 不会触发重载，
   所以脚本用附加唯一 query 的方式强制整页加载，保证每条路径从干净状态起跑。
2. **页内点击只在手机画面（`#app`）里找按钮**：顶部演示控制条里也有文字相近的按钮
   （例如「⑤ 女儿未回应」和页面内的「我来回应」），不限定范围会点错。
