# 页面与状态清单

> 本清单是原型的**唯一依据**：每一项都能在可操作原型中定位到画面（路由列）。静态截图与可操作演示对应同一版本（`原型图/` 目录，编号一致）。
> 路由为原型内 hash 路由，可直接访问；编号为唯一 ID。
> 事务样例：**服药（每日 08:00 / 20:00）**、**取快递（截止型）**、**缴水费（每月 15 日前）**、**买菜（每周二 09:30）**。

## 三、演示支持的案例（范围说明）

原型**仅保证以下案例路径内的操作成立**，不处理任意输入：

1. **主案例 · 正常完成**：E3 → E5 →「我做完了」→ E3 状态变为已完成；家属端 F1 只进日志不推送。
2. **语音案例**：E5 → E6 → 说出预设句子 → 复述 →「对」→ 回 E5。
3. **纠错案例**：E6 复述与实际不符 →「不对」→ E7 → 选候选 → 回 E6 重新复述。
4. **家属录入案例**：F1 → F2 说"每周二上午九点半买菜" → F3 看 AI 识别结果 → 改一处 → 确认 → 老人端 E3 出现新待办。
5. **求助案例（老人发起）**：E5 → E10 → E11 →（切女儿）F1 → F4 → F5 留言 →（切老人）E12。
6. **系统升级案例**：E5 超时/演示直达 → 系统通知女儿 → 同上。
7. **取消案例**：E11 → 取消求助 / E4 → 今天做不了 → E9；女儿端 F8。
8. **家属未回应案例**：E11 → 演示直达 → E13 → 替代方案。
9. **改期案例**：F5 → F6/改期 → 提交 →（切老人）E14 → 老人同意 → E3 晚间时间已更新。
10. **网络失败案例**：E5 → 演示直达 → E15 → 再试一次。

> 未纳入范围的设想（不设空按钮）：智能药盒硬件、跌倒检测、定位共享、紧急呼叫 120、真实网购/缴费、多老人管理。见《01-产品说明.md》§2.2。
