# 演示说明

> 面向评审：照着本文件可以在 5 分钟内走完主流程、异常流程与协作流程。

---

## 一、访问方式

| 项 | 值 |
|---|---|
| 启动 | 仓库根目录执行 `docker compose up --build` |
| 访问地址 | **http://localhost:8080** |
| 备用启动（无 Docker） | `python -m http.server 8080` 或 `npx serve -l 8080`，同样访问 http://localhost:8080 |
| 页面形态 | 单页应用，hash 路由；**不需要服务端 rewrite** |

## 二、主要演示设备与尺寸

| 项 | 值 |
|---|---|
| 目标形态 | **移动端（Web / 手机）**，本次只设计手机形态，不做平板与桌面版 |
| 画布尺寸 | **390 × 844 逻辑像素**（iPhone 14/15 系列）、D-Pad 圆角机身 |
| 老人端排版基线 | 正文 ≥ 28px、主按钮高 ≥ 78px、对比度 ≥ 4.5:1、无键盘输入 |
| 家属端排版基线 | 正文 16px、按钮高 ≥ 46px（女儿是熟练用户，可用常规密度） |
| 无障碍 | 老人端设置页提供「字再大一点」开关，可再放大一档 |

> 原型在桌面浏览器打开时，画面被居中限制在 390px 宽的"手机"里，两侧留白 —— 这是有意的：老人端的信息密度就是按手机定的。

## 四、推荐的 8 步演示脚本

> 全程只用顶部演示控制条 + 页面内大按钮，不需要输入任何文字。

| 步骤 | 操作 | 看到什么 | 对应编号 |
|---|---|---|---|
| 1 | 初始页面 | 首次建立协作的空状态：还没有待办、还没连女儿 | E1 |
| 2 | 点「让女儿帮我安排」 | 关系确认页，**明确写出女儿能看到什么、看不到什么**；点「同意连上」 | E2 |
| 3 | 回到首页 | 今日 4 件事按时间排好；早上那顿已打勾；取快递标「今天到期」 | E3 |
| 4 | 点「20:00 吃降压药（晚上）」→「我做完了」 | 完成、回首页并给出"记上了，女儿那边看得到"的结果反馈 | E4 → E5 → E3 |
| 5 | 控制条点「③ 识别有误」（直达复述画面） | AI 把"晚上"听成"早上"，**先复述再确认**；点「❌ 不对」 | E6 → E7 |
| 6 | 在纠错页点「是晚上的药，不是早上」 | 复述被改对，再点「✅ 对」完成 —— 识别错误被用户纠正 | E7 → E6 → E3 |
| 7 | 控制条点「④ 等待女儿」→ 切到「👩 张莉」 | 老人端显示"已告诉女儿"；家属端首页出现**红色异常横幅**，点开能看到"是妈妈主动求助" | E11 → F1 → F4 → F5 |
| 8 | 家属端点「🎤 录一句语音留言给她」→ 切回「👵 张阿姨」 | 老人端收到回执"女儿回话了"，能看到她说了什么 | F5 → E12 |

**另外值得单独看的三条**（都用控制条直达）：

- **⑤ 女儿未回应**：等 30 分钟女儿还没看 → 老人端不静默等待，给「直接打电话」「找社区医生」「再等一会儿」三条出路。（E13）
- **⑥ 确认改时间**：女儿想把晚上的提醒从 20:00 改到 19:30 → 老人端弹出确认页，**没点头就不生效**。（F5 → E14）
- **⑧ 女儿语音录入**：点 ⑧ 直达"正在听"，1.2 秒后自动给出 AI 识别结果 + 原文对照 → 改一处 → 确认 → 切到老人端，新待办出现。（F2 → F3 → F6 → E3）

**另外值得单独看的四条新增状态**：

- **拒绝授权（S18）**：E1 点「我自己来，先看看」/ E2 点「先不连」→ 老人端首页显示「还没连上女儿」（可补连）→ 切女儿：家属端只有"还没有和妈妈连上"，**看不到任何事务**。
- **共享关闭（S19）**：E17 关掉「今天做没做」「一周记录」「帮你改提醒时间」→ 切女儿：F1 不再列事务、F7 不再有趋势与建议、F5 不再出现改期入口，每一处都有说明文字。
- **老人发起添加（S20）**：E3 →「我想加一件事」→ 说一句 → AI 复述 →「对」→ 切女儿：F1 出现「妈妈想加一件事」→ F3 确认 → 切回老人端：新待办出现。
- **取消联动撤回（S9 加强）**：先让老人求助（E5→E10→E11），再回 E4 点「这件事今天做不了」→「今天先不做」→ 切女儿：家属端**不会再显示**「妈妈找你帮忙」，而是显示「妈妈撤回了求助」横幅，点进去就是 F8。

## 五、进入各关键状态的方法

两条路都行：**控制条直达**（最快）或**沿路径点击**（更像真实使用）。

| 状态 | 控制条直达 | 沿路径点击 |
|---|---|---|
| S1 首次建立协作 | ① | 起始页即此状态 |
| S2 正常有数据 | ② | E1 →「我自己来」 |
| S3 提醒详情 / 截止型 | — | E3 → 点「去驿站取快递」 |
| S4 处理中（等女儿） | ④ | E3 → 晚间药 → E5 →「叫女儿帮忙」→ E10 →「告诉她」 |
| S5 家属回应成功 | ④ 后走完第 7–8 步 | E11 →（切女儿）F1 → F4 → F5 留言 →（切回）E12 |
| S6 识别或理解有误 | ③（直达复述画面） | E3 → 晚间药 → E5 →「用语音说」→ 按住说话 |
| S7 失败及重试（听不清） | 直接访问 `#/elder/voice/med-evening?fail=2` | E6 →「🎤 再说一遍」两次可复现 |
| S8 修改（老人确认改期） | ⑥ | F1 →（女儿）F5 →「帮她改提醒时间」→ 选 19:30 → 切回老人端 |
| S9 取消 / 撤回 | ④ →「取消求助」 | E4 →「这件事今天做不了」→ E9；或 E11 →「取消求助」 |
| S10 家属未回应 | ⑤ | E11 停留 30 分钟后（演示直达） |
| S11 老人主动求助 | ④ 前半段 | E5 →「叫女儿帮忙」 |
| S12 网络失败 | ⑦ | E5 确认时断网（演示直达） |
| S13 空状态 / 数据不足 | — | 直接访问 `#/elder/history?empty=1`、`#/family/log?empty=1` |
| S14 家属端正常日 | 角色切「👩 张莉」 | 无异常时即为该状态 |
| S15 家属端识别纠正 | ⑧ | F1 →「➕ 帮妈妈记一件事」→ 按住说 |
| S16 老人端添加事务 | — | E3 →「➕ 我想加一件事」→ 按住说 |
| S18 未建立协作（老人拒绝） | — | E1 →「我自己来」/ E2 →「先不连」，再切女儿 |
| S19 共享项已关闭 | — | E17 关掉任意共享项，再切女儿看 F1 / F7 / F5 |
| S20 老人发起添加闭环 | — | E3 →「我想加一件事」→ 说一句 → 切女儿确认 → 切回老人 |
| S21 帮助看图说明 | — | E17 →「📖 怎么用（看图说明）」 |

> 全部 **26 个页面（老人端 E1–E17 + 家属端 F1–F9）**都有独立路由，可直接改浏览器地址栏访问，
> 例如 `#/elder/waiting/med-evening`、`#/family/review?manual=2`。直接访问时原型会**自动补齐该画面所需的演示数据**，不会出现空白页。
> 任务 id 用的是 `med-evening`（晚上那顿药）这类完整 id，不是简写。

## 六、恢复初始演示状态

两种方式，效果相同：

1. 点演示控制条最右侧的 **「↺ 恢复初始状态」**；
2. 直接**刷新浏览器**。

> 原型所有状态都只存在页面内存里（没有 localStorage、没有后端），所以刷新一定回到初始状态。这也是"不依赖评审持有候选人环境"的一部分。

## 七、哪些是模拟的（逐条标注，不让评审误会）

| 看起来像真的 | 实际是什么 |
|---|---|
| AI 把语音转成文字 / 结构化待办 | **预设结果**。老人端识别为"晚上听成早上"（演示纠错），家属端识别为"每周二 09:00"（演示纠正），老人端添加事务识别为"每周四上午量血压"。没有接入任何 ASR / LLM。 |
| 语音播报、按住说话 | **交互占位**。按住说话 1.2 秒后直接进入预设识别结果，没有真正录音。 |
| 女儿的语音留言 | **预设文本**："妈，药在电视柜第二层，白色的那板。你吃了跟我说一声。" F4 里「▶ 点这里听」点一下只弹**播放提示条**，没有真实录音。 |
| "已等 N 分钟"计时 | 进页面从 3 开始每秒 +1，**纯前端计时**，与真实时间无关。 |
| "系统通知了女儿"、"30 分钟没回应" | **预设状态**，由控制条/按钮触发，没有真实消息通道与定时任务。 |
| 打电话、找社区医生 | 点一下只弹**提示条**，不真的拨号。 |
| 一周趋势、建议与"AI 识别纠错记录" | **写死的演示数据**；建议卡里的"依据"是构造的样例，代表"AI 会写明依据"，不是真实统计。 |
| 网络失败 | 预设状态，不真的断网。 |

**没有模拟偏差的地方**：页面结构、状态流转、权限规则（拒绝协作 / 共享开关对家属端实时生效）、老人点头才生效的确认链、取消与求助的联动撤回、"妈妈想加的事"从老人到家属确认再到老人端生效的闭环、家属端「动态」来自演示中的真实操作 —— 这些是本次真正要看的交付内容。

## 八、评审时的自查清单

- [ ] `docker compose up --build` 成功，浏览器能打开 http://localhost:8080
- [ ] 老人端与家属端都能进入，角色切换正常
- [ ] 正常完成能走通，且家属端**收到日志但不弹异常**
- [ ] AI 识别错误能纠正，纠正后结果正确
- [ ] 取消后老人端与家属端**状态一致**（不出现"已撤回"又"已发送成功"）
- [ ] 老人取消事务时，家属端**不再显示**「妈妈找你帮忙」，而是「妈妈撤回了求助」并可点进 F8
- [ ] 老人点「我自己来」/「先不连」后，**真的保持未连接**，家属端看不到任何事务
- [ ] E17 关掉的共享项，家属端 F1 / F7 / F5 **立即看不到**
- [ ] 老人加的事，家属端有待确认项，确认后老人端真的出现
- [ ] 家属未回应状态有独立画面且给出替代方案
- [ ] 家属改时间**必须老人同意**才生效
- [ ] 「恢复初始状态」有效
- [ ] 文档、原型图、源码三者对得上（编号一致）
